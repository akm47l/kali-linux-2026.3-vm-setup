# التثبيت وإدارة الأقراص

## إعداد المضيف

ثبّت QEMU وqemu-img وPython 3 وflock. لتثبيت Kali يلزم أيضاً curl وGnuPG وsha256sum. لا يلزم KVM؛ في غيابه يستخدم البرنامج TCG تلقائياً. افحص المضيف بـ `./kali.sh check`.

## إعداد كلمة VNC محلية

مصادقة VNC التقليدية تقبل 1–8 بايتات ASCII فقط. يرفض البرنامج القيمة الأطول حتى لا يوحي بأن كاملها محمي. اختر عبارة قوية قصيرة، واحفظها في الملف التالي بصلاحيات خاصة، ولا تكتبها في الدردشة أو سطر الأوامر:

```bash
install -d -m 700 "$HOME/.config/kali-virtual-security-lab"
umask 077
read -rsp 'VNC password (1-8 printable ASCII characters): ' VNC_PASSWORD
printf '\n'
printf '%s' "$VNC_PASSWORD" > "$HOME/.config/kali-virtual-security-lab/vnc-password.txt"
unset VNC_PASSWORD
chmod 600 "$HOME/.config/kali-virtual-security-lab/vnc-password.txt"
```

لا تمرر كلمة المرور في وسيطات QEMU أو سجل؛ يضبطها البرنامج عبر QMP خاص بالمستخدم. إذا كان الحساب المحلي غير موثوق، لا تعتمد على VNC وحده كحاجز بين المستخدمين.

## تثبيت Kali من صورة رسمية

`./kali.sh install`:

1. يرفض مسار قرص موجوداً ولا يحذفه أو يستبدله.
2. ينزّل الصورة وملفات `SHA256SUMS` و`SHA256SUMS.gpg` من `https://cdimage.kali.org/kali-<release>/` فقط.
3. يتحقق من توقيع manifest بمفتاح Kali ذي البصمة `827C 8569 F251 8CC6 77FE CA1A ED65 462E C8D5 E4C5`، ثم يطابق SHA-256 للصورة.
4. يفحص وجود مساحة للتنزيل، ويحفظ ISO في `~/.local/share/kali-virtual-security-lab/installer/` بصلاحية خاصة.
5. ينشئ قرص QCOW2 جديداً بسعة افتراضية مضبوطة في `DISK_SIZE` (الافتراضي 80G) ويبدأ المثبّت التفاعلي.

تتبع خطوة التحقق [إرشادات Kali الرسمية للتحقق من الصور](https://www.kali.org/docs/introduction/download-official-kali-linux-images/) وقائمة [التنزيلات الرسمية](https://www.kali.org/get-kali/). لا تعتمد على checksum منفرداً: يتطلب السكربت توقيع manifest ببصمة المفتاح المثبتة ثم يطابق hash الملف.

حجم ISO لـKali 2026.3 عند كتابة هذا الإعداد يقارب 4.7 GiB؛ قد يتغير في الإصدارات اللاحقة. التنزيل لا يحدث إلا عند تنفيذ install، ولا تشغله الاختبارات.

اختر القرص الافتراضي الجديد داخل برنامج التثبيت، وأدخل كلمة مرور مستخدم Kali بنفسك. لا يمرر السكربت `preseed.cfg` تلقائياً ولا يضع كلمة مرور أو hash افتراضياً.

## إعداد المستخدم واختيار ملفه

الإعدادات المشتركة الآمنة في `config/defaults.conf`. انسخ [مثال الإعداد](../config/local.conf.example) إلى:

`~/.config/kali-virtual-security-lab/config.conf`

ثم عدّل مثلاً `MEMORY=3G` أو `NETWORK_MODE=OFFLINE` أو `DISK_SIZE=100G`. تنسيق الإعداد `KEY=value` ولا يقيم تعليمات shell. أدلة البيانات والوقت التشغيلي لكل مستخدم منفصلة. `DISK_PATH` و`VNC_PASSWORD_FILE` يقبلان اسم ملف بسيطاً فقط، ويحفظهما البرنامج داخل مجلدي البيانات والإعدادات الخاصين بالمستخدم؛ تُرفض المسارات المطلقة وأي فواصل أدلة أو محاولات `..`.

## إنشاء قرص منفصل

```bash
./kali.sh create-disk --size 80G
```

الملف sparse؛ سعته الافتراضية لا تعني تخصيص كامل المساحة فوراً. مع ذلك، يشترط السكربت مساحة حرة تبلغ على الأقل 10% من السعة (وبحد أدنى 2 GiB) للحد من خطر امتلاء المضيف. `--output` يقبل اسماً داخل مجلد بيانات المستخدم، لا مساراً مطلقاً أو فرعياً. لا يكتب على ملف موجود. لا تنقل ملف القرص أو تحذفه بينما QEMU يعمل.

## النسخ واللقطات والاستعادة

أوقف Kali أولاً. التشغيل وعمليات القرص تستخدم قفلاً مشتركاً لكل مستخدم؛ ترفض العملية الجديدة البدء إذا كانت آلة أو عملية قرص أخرى تحمل القفل، ويُحتفظ به طوال فحص/تعديل QCOW2. `./kali.sh backup` ينشئ نسخة QCOW2 مستقلة ويتحقق منها؛ لا يحذف نسخة سابقة. `./kali.sh snapshot` يعرض اللقطات، و`./kali.sh snapshot create NAME` ينشئ لقطة داخلية مع سجل UTC لكل مستخدم. اللقطات تعتمد على تنسيق الصورة ولا تعمل مع كل أنواع الأقراص.

`./kali.sh restore NAME` يستلزم طرفية تفاعلية، وتأكيداً صريحاً، وإنشاء نسخة احتياطية قبل التغيير. لا تختبر الاستعادة على القرص الوحيد المهم؛ جرّبها على نسخة منفصلة أولاً.

## preseed

`preseed.cfg` مثال قابل للتخصيص، وليس جزءاً من مسار تثبيت `kali.sh install`. راجع [دليل Debian الرسمي لإعدادات preseed](https://www.debian.org/releases/trixie/amd64/apbs04.en.html). لا يختار ملفنا قرصاً ولا يوافق تلقائياً على الكتابة أو يعيّن كلمة مرور. راجع الجهاز الهدف في واجهة المثبّت دائماً؛ لا تستخدم إعداداً آلياً على قرص يحوي بيانات.
