# Kali Virtual Security Lab

مختبر افتراضي لتثبيت Kali Linux وتشغيله بأمان على مضيف Linux عبر QEMU. يحتوي على واجهة أوامر واحدة، إعدادات موارد قابلة للتخصيص، ثلاثة أوضاع للشبكة، إنشاء أقراص QCOW2، فحوصات للسلامة، نسخ احتياطية ولقطات. صور Kali والأقراص الافتراضية وكلمات المرور لا تُخزَّن في GitHub.

> استخدم المختبر على أنظمة وشبكات تملكها أو لديك تصريح صريح لاختبارها. لا تفعّل bridge ولا تعرّض خدمات المختبر على واجهة عامة.

## المتطلبات

- مضيف Linux؛ اختُبر المشروع على Ubuntu 24.04 وQEMU 8.2.2، ويستخدم أوامر متوافقة مع QEMU/QEMU-img الحديثة.
- `bash`، و`python3`، و`flock`، و`qemu-system-x86_64`، و`qemu-img`.
- للتثبيت: `curl` و`gpg` و`gpgv` و`sha256sum`.
- KVM تحسين اختياري. يكتشفه المشروع تلقائياً ويستخدم TCG عندما لا يتاح؛ لا يشترط KVM.

شغّل `./kali.sh check` لفحص المتطلبات والموارد وصلاحيات الملفات وقرص QCOW2 إن وُجد. الاختبارات الأساسية لا تتطلب تنزيل ISO أو تثبيت Kali.

## فصل الجلسات بين مستخدمي Linux

لكل حساب Linux إعداداته وقرصه وكلمة مروره ومجلدات التشغيل الخاصة به، ولا تعرض أوامر `status` و`stop` جلسات الحسابات الأخرى. تُحفظ الملفات افتراضياً في:

- البيانات والأقراص: `~/.local/share/kali-virtual-security-lab/`
- الإعدادات وكلمة VNC: `~/.config/kali-virtual-security-lab/`
- المقابس وملفات PID والسجلات: `$XDG_RUNTIME_DIR/kali-virtual-security-lab/`، أو مجلد خاص بالمستخدم تحت `/tmp` عند غياب XDG runtime.

تُنشأ المجلدات بصلاحية `700` والملفات السرية بصلاحية `600`. لا تشارك مجلدات البيانات أو ملفات كلمة المرور بين الحسابات. تعمل آلة واحدة لكل مستخدم في نسخة المستودع نفسها. يُختار منفذ VNC ومنفذ SSH من منافذ loopback المتاحة؛ وقد يلزم تغييرهما يدوياً إذا كانت منافذ المضيف مشغولة.

تقبل إعدادات `DISK_PATH` و`VNC_PASSWORD_FILE` ووسيط `create-disk --output` أسماء ملفات فقط، لا مسارات مطلقة أو `../`؛ تبقى الأقراص وكلمات المرور داخل أدلة المستخدم الخاصة.

**حدّ أمني مهم:** منافذ `127.0.0.1` محلية للمضيف لكنها ليست خاصة بحساب Linux؛ يمكن للمستخدمين المحليين الآخرين محاولة الوصول إليها. كلمة VNC التقليدية لا تستخدم إلا أول 8 بايتات، لذلك لا تُعاملها كحدّ أمني قوي ضد مستخدم محلي عدائي. للمنافذ البعيدة استخدم نفق SSH، وحافظ على حسابات نظام منفصلة وصلاحيات الأدلة الخاصة. المستخدم ذو صلاحيات root يستطيع الوصول إلى عمليات وملفات المضيف.

## تثبيت Kali

1. أنشئ كلمة مرور VNC محلية آمنة حسب [دليل التثبيت](documentation/INSTALLATION.md). يجب أن تكون من 1 إلى 8 محارف ASCII قابلة للطباعة بسبب قيد بروتوكول VNC التقليدي.
2. راجع المساحة المتاحة واسم ملف القرص في `~/.config/kali-virtual-security-lab/config.conf` (الافتراضي `80G` كسعة افتراضية sparse؛ يمكن تخصيص الاسم والحجم).
3. نفّذ `./kali.sh install` من نسخة جديدة. ينزّل السكربت فقط من `cdimage.kali.org`، ويتحقق من توقيع `SHA256SUMS` بمفتاح Kali ذي بصمة مثبتة، ثم يطابق SHA-256 قبل حفظ ISO. لا يستبدل قرصاً موجوداً.
4. يفتح المثبّت التفاعلي على QEMU. اختر القرص الافتراضي الجديد في واجهة التثبيت، وضع كلمة مرور Kali أثناء التثبيت. لا يمرر المشروع ملف `preseed.cfg` تلقائياً.
5. بعد إيقاف المُثبّت، استخدم `./kali.sh start`.

الـ ISO محفوظ في مجلد بيانات المستخدم الخاص، وليس داخل المستودع. التنزيل المتوقع للإصدار 2026.3 يقارب 4.7 GiB؛ لا يُنزّل أثناء الاختبارات.

## التشغيل والأوامر

```bash
./kali.sh help
./kali.sh check
./kali.sh start
./kali.sh status
./kali.sh stop
./kali.sh restart
./kali.sh snapshot
./kali.sh snapshot create before-update
./kali.sh backup
./kali.sh restore before-update
```

يطلب `restore` تأكيداً نصياً مطابقاً وينشئ نسخة byte-for-byte قبل استعادة لقطة. `stop` يطلب إيقافاً نظامياً عبر ACPI؛ إذا لم يستجب الضيف، أوقفه من داخله، ولا تستخدم `./kali.sh stop --force` إلا عند قبول احتمال فقد آخر تغييرات القرص. ينتظر `restart` تحرير قفل الجلسة السابقة ثم يمرره للتشغيل الجديد. لا تُحذف الأقراص أو النسخ الاحتياطية أو اللقطات تلقائياً.

## ملفات الإعداد والموارد

اختيار ملف أداء:

```bash
./kali.sh --profile minimal check
./kali.sh --profile standard start
./kali.sh --profile advanced start
```

- `minimal`: 2 GiB و1 vCPU.
- `standard`: 4 GiB واحتساب تلقائي لأنوية CPU (حتى 4 أنوية).
- `advanced`: 8 GiB و4 vCPU.

تُفحص الموارد قبل البدء، ويُترك 512 MiB على الأقل للمضيف. عدّل نسخة إعدادات المثال إلى `~/.config/kali-virtual-security-lab/config.conf`؛ الملف يُقرأ كمفاتيح `KEY=value` بسيطة ولا يُنفَّذ كـ shell. يجب أن تكون `DISK_PATH` و`VNC_PASSWORD_FILE` أسماء ملفات بسيطة بلا مسارات؛ لا تضع كلمات مرور أو مفاتيح في الملف.

## أوضاع الشبكة

عيّن `NETWORK_MODE` في ملف الإعداد الخاص بالمستخدم:

- `OFFLINE`: لا تُرفق بطاقة شبكة افتراضية.
- `NAT` (الافتراضي): اتصال QEMU user-mode NAT، وتحويل SSH إلى منفذ على `127.0.0.1` فقط.
- `ISOLATED`: مقبس Unix خاص بالمستخدم للتواصل بين آلات QEMU المحلية؛ لا يفعّل إنترنت أو bridge.

راجع [NETWORKING](documentation/NETWORKING.md) للتفاصيل. لا توجد قاعدة تحويل منافذ على واجهة عامة ولا bridge تلقائي.

## الأقراص والنسخ واللقطات

`./kali.sh create-disk --size 80G` ينشئ ملفاً جديداً sparse فقط، ويفشل إذا كان الملف موجوداً. يفحص مساحة المضيف ويحافظ على الملفات القديمة. تستخدم عملية التشغيل وكل أوامر تعديل/فحص QCOW2 قفلاً مشتركاً ممتداً طوال العملية؛ إذا كانت الآلة تعمل أو كان فحص/تعديل آخر جارياً، تُرفض العملية المتعارضة بدلاً من المخاطرة باتساق القرص. اللقطات الداخلية مدعومة فقط عندما يسمح بها تنسيق QCOW2؛ لا تحذفها الأداة تلقائياً. يراجع [دليل التخزين](documentation/INSTALLATION.md) قبل تغييرات القرص.
